# Поиск запчастей — локальный запуск и описание приложения

Приложение представляет собой интерфейс для поиска запчастей по артикулу с последующим выбором бренда и просмотром аналогов деталей у других брендов. Оно использует стек React + Vite + Redux Toolkit, имеет обработку ошибок, UX-валидацию ввода, дебаунс запросов, фильтрацию и сортировку результатов для удобного сравнения цен и остатков.

## 1) Локальный запуск приложения

Ниже — подробная инструкция запуска проекта на локальной машине.

### Требования

- Node.js 18+ (рекомендуется 20/22)
- npm 9+

### Установка зависимостей

Откройте терминал в директории проекта и выполните:

```bash
npm install
```

Если зависимости уже установлены, можно сразу перейти к запуску.

### Запуск в режиме разработки

```bash
npm run dev
```

После запуска в терминале появится адрес локального сервера, обычно:

```bash
http://localhost:5173/
```

Откройте этот URL в браузере.

### Сборка проекта

Для production-сборки:

```bash
npm run build
```

После этого будут собраны статические файлы в папку `dist/`.

### Основные команды

```bash
npm run dev       # запуск разработки
npm run build     # сборка проекта
npm run build:ci  # CI/production: lint + тесты + сборка
npm run preview   # просмотр собранной версии
npm run lint      # проверка ESLint
npm run test      # запуск unit-тестов
npm run test:watch # watch-режим тестов
npm run check     # lint + test
```

## 2) Что делает приложение

Это приложение предназначено для поиска и сравнения запчастей по номеру детали.

Пользователь вводит номер детали (Я разрешила только цифры и латинские буквы, это не уточнялось в требованиях, но как-то валидировать же надо), после чего:

1. приложение выполняет поиск по артикулу;
2. получает список брендов, в которых есть деталь с таким артикулом;
3. пользователь выбирает бренд;
4. приложение загружает данные об этой детали с аналогами в других брендах;
5. результат отображается под списком брендов.

## 3) Как приложение обрабатывает ошибки

В проекте ошибки обрабатываются на нескольких уровнях:

### 3.1 Валидация ввода

Если пользователь пытается ввести в поле поиска символы, кроме цифр и латинских букв, то:

- включается валидация HTML5;
- выводится сообщение об ошибке;
- поле помечается `aria-invalid`;
- дальнейшие запросы не отправляются.

Сообщение:

```text
Номер детали может содержать только цифры и латинские буквы
```

### 3.2 Отмена предыдущих запросов

Для избежания гонок запросов используются:

- `debounce` через `setTimeout` (500ms), чтобы запросы не уходили слишком часто при быстром вводе;
- отмена предыдущего незавершенного запроса с помощью `AbortController` при каждом новом вводе, чтобы старые запросы не перетирали результаты новых.

### 3.3 Async thunk и обработка ошибок

Для загрузки брендов и товаров используется Redux Toolkit `createAsyncThunk`.

Логика обработки:

- Отменённый запрос игнорируется;
- остальные ошибки преобразуются в текстовое сообщение, которое выводится в UI.

## 4) Логика показа результатов: фильтрация и сортировка

### 4.1 Фильтрация

Из списка аналогов удаляются позиции с нулевой ценой.
Ничего подобного в требованиях не было, но это показалось мне логичным.

### 4.2 Сортировка

Список аналогов сортируется так:

- Сначала детали в наличии, в конце списка детали без остатка;
- внутри групп сортировка по возрастанию цены.

Т.е. в самом начале будет отображаться самый дешевый аналог в наличии.

## 5) Что используется в проекте

### Фреймворк и сборка

- React 19
- Vite 8
- JavaScript (ES modules)

### Состояние приложения

- Redux Toolkit
- React Redux
- slice-архитектура для хранения данных о брендах, поиске, выбранном бренде и результатах запросов

### API и сеть

- `fetch()` для общения с внешним API
- `AbortController` для отмены запросов
- `createAsyncThunk` для асинхронной загрузки данных

### UI

- Bootstrap 5
- кастомные SCSS-стили
- responsive layout
- accessibility-метки (`aria-live`, `aria-invalid`, `role="alert"` и т.д.)

## 2) Тесты

В проекте добавлены unit-тесты на ключевую логику:

- reducer / async-thunk сценарии для поиска брендов и аналогов;
- селекторы условий отображения списка брендов, ошибок и пустых состояний;
- сортировку и фильтрацию таблицы аналогов;
- базовый UI-сценарий для валидации и ввода артикула.
